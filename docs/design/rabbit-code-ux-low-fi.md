# Rabbit Code 低保真信息架构与主流程

<!-- RC ID: RC-254. This document freezes the review scope before further GUI expansion. -->

## 评审范围

本稿冻结工作区的入口、主旅程、任务输入区和返回规则。它描述现有页面之间的责任边界，不引入新的功能页面。代码实现以这些边界为准，页面细节由高保真稿和 Design Token 约束。

## 信息架构

```text
Rabbit Code
├── 首页 /workspace/home
│   ├── API 路线 -> /workspace/providers?entry=api
│   ├── 本地路线 -> /workspace/models?entry=local
│   └── 已有工作区 -> /workspace
├── 工作区 /workspace
│   ├── 对话输入与发送
│   ├── 菱形星星优化 -> 结果预览 -> 采用/保留原文
│   └── 优化结果 -> /workspace/review 或历史比较
├── 任务 /workspace/task
├── 变更审查 /workspace/review
├── 终端 /workspace/terminal
├── Provider 与模型 /workspace/providers
├── 本地模型 /workspace/models
├── 提示词资产 /workspace/assets
├── 设置 /workspace/settings
└── 诊断 /workspace/diagnostics
```

入口页面只负责选择路线。配置页负责可用性和恢复，工作区负责输入/优化/发送，Review 负责采用或拒绝变更；任何错误都保留当前输入并提供返回或恢复动作。

## 主旅程

### API 用户

```text
首页 -> 配置 Provider -> Mock 连接验证 -> 工作区
     -> 输入任务 -> 菱形星星优化 -> 预览 diff
     -> 采用或保留原文 -> 发送 -> 流式状态/结果
```

### 无 API 用户

```text
首页 -> 检测硬件 -> 选择 Gemma/Qwen -> 安装/校验/健康检查
     -> 工作区选择本地模型 -> 输入任务 -> 发送或菱形星星优化
     -> 本地结果；模型未就绪时明确显示离线规则降级
```

### 返回、取消和错误

```text
编辑输入 -> 取消/返回       : 输入保留
Provider 错误 -> 重试/切换路线: 输入保留
优化完成且输入未变 -> 结果预览: 不自动覆盖输入
优化完成但输入已变 -> 待比较   : 先查看比较或重新优化
```

## 关键线框

### 首页双入口

```text
+------------------------------------------------------------------+
| Rabbit Code                                      [设置]          |
+----------------------+-------------------------------------------+
|                      |  我们该构建什么？                          |
|  [新建任务]          |  [探索代码] [构建功能] [审查代码] [修复问题] |
|  项目 / 任务         |                                           |
|  技能 / 插件         |  [配置 API Provider] [安装本地模型]          |
|                      |  [打开已有工作区]                           |
+----------------------+-------------------------------------------+
```

### 工作区输入区

```text
+------------------------------------------------------------------+
| 当前工作区  | 执行环境 [本地/Provider] | 执行状态 [空闲/执行中]    |
|------------------------------------------------------------------|
| 描述你想要完成的任务...                                         |
|                                                                  |
|                                      [提示词控制] [星星] [发送]   |
+------------------------------------------------------------------+
| 状态 / 错误 / 优化结果预览 / 历史 / diff                         |
+------------------------------------------------------------------+
```

线框中的按钮顺序固定为“上下文控制 -> 优化 -> 发送”。优化是可取消、可比较的独立动作，发送是显式提交动作；两者不能互相触发。

## 冻结决策

- 首页只承担路线选择和已有工作区入口，不承载 Provider 细节。
- 工作区输入区保持固定三段元信息、文本输入和动作区结构。
- 优化结果先进入可编辑预览，发送动作不自动采用优化结果。
- 错误、取消和切换路线均保留原始输入。
