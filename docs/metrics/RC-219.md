# RC-219 Technical Metrics

## Boundary

Rabbit Code aggregates these metrics in local memory under schema `rc219-v1`.
The report contains no prompt, source, path, credential, request body, or raw
Provider response. Provider and model labels are restricted technical IDs;
labels containing credential-like terms are rejected.

## Definitions

| Metric | Unit | Definition |
| --- | --- | --- |
| `total_latency_ms` | ms | End-to-end Provider request latency reported by the adapter or stream. |
| `first_token_total_ms` | ms | Time from stream start to the first non-empty text delta. |
| `input_tokens`, `output_tokens` | tokens | Provider-reported usage when available; unknown usage remains zero. |
| `failure_rate` | ratio | Failed requests divided by total recorded requests. |
| `tool_success_rate` | ratio | Successful tool results divided by recorded tool calls; `0/0` is `0`. |
| `average_model_load_ms` | ms | Mean duration of local runner model-load operations. |
| `max_cpu_percent` | percent | Maximum local system load estimate converted to a bounded percentage when available. |
| `max_ram_bytes`, `max_gpu_memory_bytes` | bytes | Maximum sampled RAM and GPU memory values. |

## Reproducible Report

The fixed-load fixture `backend/tests/test_rc219_metrics.py` records two
requests, one first-token sample, one successful tool result, one model load,
and one resource sample. It asserts the exact aggregate values and the
absence of content fields. `GET /api/v1/metrics` returns the same versioned
snapshot shape after the application has collected live samples.

No metrics upload endpoint is implemented. Anonymous reporting, if added,
requires explicit opt-in under RC-220.
