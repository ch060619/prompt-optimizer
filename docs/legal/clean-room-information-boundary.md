# Clean-room 人员与信息边界

RC IDs: RC-025

## 当前状态

角色登记为 `pending-human-signoff`。在真实研究者、实现者和审查者完成身份、权限和签署前，本文件提供项目默认隔离规则，不声称已经完成组织层面的授权配置。

## 角色隔离

研究者只把合法公开材料和可观察行为转换成中立规格。中立规格只能描述输入、输出、状态、错误、权限约束、数据边界和不确定性；不得包含 source filename、代码结构、原文、私有 Prompt、内部测试或专有资产。

实现者只能接收已审查的中立规格、官方公开文档/SDK 和许可证清晰的来源。实现者账号、工作树、CI 缓存、依赖树、Docker 层和发布目录不得访问 source-map 还原仓库或其正文。

审查者检查角色权限、Provenance、规格内容、diff 和扫描报告，记录日期、范围、结果和未解决问题。所有沟通进入 Issue 或 PR，不通过未审计的文件、聊天附件或复制粘贴传递受限材料。

## 信息流

```text
合法材料/黑盒观察
        |
        v
研究者 -> 中立行为规格 -> 审查者 -> 实现者
        |                         |
        +---- 原始受限材料不得流入实现工作树、CI、依赖或制品 ----+
```

## 抽查规则

- 抽查 clean-room 规格不得出现源文件名、原文片段、代码块、私有常量或未经批准的来源标识。
- 抽查实现 PR 必须有 Provenance 段，并能说明每个外部来源的许可证和使用方式。
- 发现越界材料时立即停止该 PR 的合并，隔离材料，记录事件，并回到 RC-022 的法律复核边界。
