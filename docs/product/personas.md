# RC-037 目标用户 Persona

RC IDs: RC-037

## 研究状态

状态：`evidence-calibrated-not-interview-validated`；产品范围评审：`pending-product-review`。

本轮依据现有执行计划、技术栈/身份 ADR、本地模型许可证政策和 RC-036 调研汇总建立 Persona。没有访谈、问卷或可代表用户群的外部样本，因此以下内容是可测试的产品假设，不是用户研究结论。

## Persona 总览

| Persona | 主要目标 | 关键约束 | P0 高频任务 |
| --- | --- | --- | --- |
| 个人开发者 | 打开仓库、完成编码任务、得到可审查 diff、减少提示迭代 | 时间有限、希望本地优先、需要看清成本和 Provider 状态 | 仓库到计划；计划到 diff；测试结果可见 |
| 无 API 用户 | 无云凭据完成分析/优化，保持源码和 Prompt 在本机 | 没有 API Key、硬件/磁盘有限、模型条款必须显式确认 | 离线优化；模型下载前看许可和数据边界 |
| 多 Provider 用户 | 切换 Provider、比较质量/成本、保护密钥 | Provider 能力/错误不同，密钥不能写入历史，切换不能丢输入 | 配置 Provider；无损切换；比较结果 |
| 开源贡献者 | 可复现地实现、测试、追踪来源和许可证 | 不得导入未批准材料，CI/NOTICE 门禁必须可重现 | 需求追踪；Provenance；运行本地/CI 门禁 |
| 团队维护者 | 统一工作流、恢复任务、控制发布风险 | 资源归属、审计历史、策略解释和有限签署人 | 审查会话；恢复任务；查看发布阻塞 |

## Persona 细节与可测任务

详细机器登记见 `docs/product/personas.yml`。每个 Persona 至少有三个高频任务，并为每个任务设定了 P0/P1 优先级和可验证结果：

- 个人开发者：仓库到计划、计划到 diff、提示优化比较/撤销。
- 无 API 用户：离线优化、模型同意、下载失败恢复。
- 多 Provider 用户：配置 Provider、无损切换、比较结果。
- 开源贡献者：需求追踪、Provenance 审查、重跑门禁。
- 团队维护者：审查会话、恢复任务、发布批准。

## 冲突需求

- 隐私与 Provider 广度：远程模型能力不能以隐藏数据边界为代价；离线路线必须可用。
- 速度与治理：自动化门禁应减少重复检查，但不能静默绕过许可证、来源和人工签署。
- 个人自由与团队策略：本地草稿和已批准发布状态要分开，并解释阻塞原因。
- 平台/Provider 广度与验证成本：未实测组合必须进入支持矩阵并标注未验证。
- 丰富视觉与高频扫描：兔兔品牌元素必须服务于识别，不遮挡代码、diff、终端和权限信息。

## 产品范围评审

核心能力由 Persona 覆盖：仓库/工作区、Agent 计划/编辑/测试/diff、离线优化、Provider/模型、会话/历史/归属、Provenance/许可证/发布门禁。

产品评审仍需确认：Persona 优先级是否符合真实用户、是否补充团队权限管理员/教育用户、P0 任务的目标时限，以及访谈样本和平台分布。没有这些确认，不把 Persona 当作最终市场规模或稳定版范围批准。
