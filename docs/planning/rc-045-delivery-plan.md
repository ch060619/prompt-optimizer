# RC-045 真实时间表与责任分工

RC IDs: RC-045

## 计划口径

这是基于 2026-07-17、单一执行槽和每周 5 个工作日的目标基线，不是对未确认人员、外部账户或未来资源的承诺。每个 RC 通过唯一工作包继承工作量、依赖、负责人、评审者、里程碑和缓冲；机器校验器会展开 `RC-001..RC-310`，拒绝重叠和遗漏。

工作量单位是工作日，已包含实现、测试、文档和提交时间；缓冲用于已记录的测试失败、数据保护和高风险依赖，不用于把未验证结果写成完成。

## 依赖与关键路径

关键路径为 `P0 -> P1 -> P2 -> P3 -> P4 -> P5 -> P6 -> P7 -> P8`。P3 依赖 P2 的表面入口，P4 依赖 P3 的优化路由，P6 依赖 P5 的安全/质量出口，P8 依赖 P7 的制品和治理出口。任何前置出口未通过时，后续包只允许做只读分析和测试准备，不得声明实现完成。

## 每周证据更新

每周更新以下字段：完成 RC ID、实际提交号、验证命令及结果、当前阻塞、缓冲消耗、下周目标。完成定义是“代码/文档已经提交，验证命令可复现，证据路径存在，主计划和追踪索引同步”；没有证据就保持 pending。目标日期变更必须保留原日期、原因、新日期和新的验收条件。
